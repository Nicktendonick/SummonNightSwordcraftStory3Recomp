# Themed beta Esc menu and session actions — 2026-09-26

The actual native runtime menu now uses the launcher's shared `storybook`
palette: parchment/cream panels, plum text/headings, blue selection and a teal
Resume button. No generated artwork or game-renderer changes were needed.
Descriptions and headings wrap; narrow windows use the existing single-column
navigation. The approved Craftknights line is retained.

## Player behavior

- Esc (or controller Guide) opens the menu. It pauses gameplay by default.
- Game has separate **Pause** and **Resume** buttons side by side. Pause keeps
  the menu visible, so Resume is immediately reachable. Resume resumes gameplay
  and closes the menu. Left/right (or D-pad) moves between the paired actions.
- **Pause while Esc menu is open** selects automatic pause (On) or a live game
  behind the menu (Off). This takes effect immediately and is remembered in
  `Settings/runtime-menu.ini` beside the launcher. The file is only created when
  the preference changes. No AppData path is involved.
- Manual Pause overrides this preference: switching automatic pause Off does not
  silently cancel a manual hold. Resume releases it. The footer's **Close menu**
  button just dismisses the menu; manual pause remains, with its pause indicator.
- Game > Reset game asks for confirmation, then cold-boots the same selected
  ROM/BIOS/battery-save combination. It briefly recreates the game window.
- Game > Close game asks for confirmation, then follows normal clean shutdown.
- Reset and Close lose unsaved progress. Neither deletes battery saves or save
  states. Cancel is the default; held Enter cannot confirm an action.
- Back/Esc cancels a confirmation first. Closing a temporarily-pausing menu
  resumes play; an explicit/manual pause stays latched until Resume.

The existing Display, Graphics, Audio, Assist and game-specific options remain.
Temporary runtime settings are session settings; a clean restart uses the
resolved launcher arguments plus the game's saved display preference file.

## Ownership and safety

- `recomp-ui`: shared palette presentation, wrapped rows, compact pause badge,
  standard Pause/Reset/Close descriptors and shared confirmation model.
- `gbarecomp`: opt-in session controls/theme, action queue, pause service at both
  normal outer-loop and present-in-place boundaries, audio pause independent of
  the mute preference. A dedicated, atomically replaced preference file controls
  menu auto-pause; a failed write retains the prior value/file. Exit code requests
  restart only after successful save flush.
- Game `src/beta_session.h`: Windows beta clean-process supervisor, using the
  already-resolved command arguments, not rerunning patch selection. One parent
  supervises all reset children; children never create supervisor chains.
  `--load-state` is removed for a genuine cold boot. Input traces get per-reset
  suffixes instead of overwriting the first trace. The beta starter's existing
  instance guard remains alive throughout.

Pause deliberately holds the guest call stack in place. It does not unwind and
redispatch an interrupted guest PC, edit registers, change game RAM, or reset
only the CPU while leaving audio/game statics alive.
